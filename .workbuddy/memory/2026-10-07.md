## ✅ T-pose / 抽搐 / UAL 开启 / 蹲姿 全部修复（commit 见下，416 用例 / 6158 断言 / 0 失败）

### ⛔ 主理人的怀疑被推翻（诚实记录）
我怀疑「轻微抽搐」是 `MikuIdleMotion` 按骨名索引抽错骨（cat 骨名带 `_NN` 后缀）。
**主理人独立复核：剥注释后 `find_bone`/`get_bone`/`set_bone`/`Skeleton3D` 各 0 次**
⇒ 它只动 `_target.position/rotation/scale`，**结构上不可能碰骨骼**。**我的怀疑错了。**

### ✅ 真根因：T-pose 与抽搐是**同一个**
cat 那条 `idle` 剪辑 = **0.0833 s + `LOOP_LINEAR`** ⇒ **每秒 12 轮**全身骨骼重写。
实测：98 条骨轨里**只有 1 条会动**（`chest_94` 偏航 0°→19.7°），**双腿骨一条轨道都没有**，且每轮弹回。
```
修复前逐帧胸yaw: 0.000 → 2.273 → 8.727 → 17.243 → 0.000(弹回)   ← 4 帧一锯齿 = 12 Hz
             双脚高度差 = 0.0000（恒定）   手 y = 1.1578（=肩高 ⇒ T-pose）
修复后：双脚高度差跨度 0.1898   手 y 0.7413~0.7629   胸yaw 恒 0.000°   翻转 0/22 帧
```

### 修法：按**内容**识别退化剪辑（不是按名字）
`is_degenerate(clip) = 时长 < 0.2s 且 会动骨轨占比 < 15%`
阈值依据（实测非拍脑袋）：cat idle = **1/98 = 1.0%**、cat ArmatureAction = **87/98 = 88.8%**、
最短真实 UAL locomotion = 0.667s ⇒ 15% 两侧余量 **15× / 5.9×**，测试要求各 ≥3×。
⚠️ 判据用「**轨道占比**」而非「首尾位移差」—— 后者对非循环剪辑会误判（起点≠终点本来就正常）。

### 🔴 最值得记的发现：**3 条测试把 bug 锁成了「正确行为」**
`test_default_off_keeps_cat_on_animation_player_path` 断言的是
「cat 有 idle 剪辑 ⇒ 不建程序化姿态」——**而那个 idle 正是 0.083s 的 T-pose 定格**，
等于**把「T-pose 不动」写成了期望行为**。另有 2 条同类。
⇒ **测试全绿 ≠ 行为正确：断言可能锁住了 bug 本身。发现这类「基线即错」时必须反转断言方向，
并在新名字里写明反转原因**（否则后人看到「基线变了」会当成漂移改回去）。

### UAL 已开 + sprint 够不到
`ual_locomotion_enabled` 默认 **true**、`ual_sprint_threshold = 1.1`。
依据：`speed_ratio = clampf(move_speed / sprint_speed, 0, 1)` ⇒ **值域恒 [0,1]** ⇒ 1.1 永不可达。
⚠️ `bot.gd:135` 用 `run_speed` 而非 `sprint_speed` 做分母，但**同样 clamp 到 1.0** ⇒ 两个调用点都不可达。
已加 `test_speed_ratio_is_clamped_to_one_at_every_call_site`（按语义锁，不写死行号）。

### 蹲姿：用 `Crouch_Fwd` 而**不是** `Crouch_Idle`（实测否决了直觉方案）
| clip | 腿角幅度 | 结论 |
|---|---|---|
