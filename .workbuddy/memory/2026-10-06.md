### 关键坑（已写进代码注释 + README known limitations）
1. `trim` 用**导入后的网格本地坐标**——glTF 导入器把 Sketchfab 的 ×100 缩放/换轴烘进了顶点，与文件原始数字差一个缩放+换轴。
2. `ArrayMesh.get_aabb()` 在网格重建后**不刷新**，核对包围盒必须用 `get_faces()` 自己算。
3. headless 下刚 `add_child` 的节点 `global_transform` 还是单位阵，工具采样要沿父链累积**本地**变换。
4. GDScript `Transform3D(轴,轴,轴,原点)` 与 `.tscn` 的 `Transform3D(12 floats)` 互为转置。

### 趴下姿态（原来仰面朝天、头朝后、悬空）
- `player._update_stance()`：`_model.rotation.x` 由 `-1.45`（≈ -83°）改为 `PI*0.5`（+90°）
  → 正面 +Z 转到 -Y（脸朝下）、头顶转到 +Z（头朝前）= 向前趴下、正面朝下。
- 贴地：新增 `MikuModel.ground_gap()`（同帧手动沿父链累乘局部变换，量当前最低点相对玩家原点的高度差），
  `_update_stance` 每帧 `_model.position.y -= ground_gap()`（**闭环**，一步到位不抖）。实测两模型 gap=0.000。

### 关键坑（本轮踩到的）
1. **测试相机要跟模型自己的坐标系走**：`main.tscn` 里 player 根相对世界转过 180°，写死世界坐标 `(0,0.95,+1.9)` 其实摆到模型背后，
   一度误判「朝向反了」。正确：用 `MikuModel.global_transform.basis.z`（= 角色正前 +Z）算机位。
2. **同帧读不了 `mesh.global_transform`**（父节点改完变换后子节点当帧未刷新）→ 量包围盒必须手动累乘 `.transform`。
3. **闭环优于预测**：一次测量算「该抬多高」会输给程序化姿态/骨骼/各模型嵌套偏移。
4. **headless 模式下 `RenderingServer.frame_post_draw` 会卡死**，离屏截图必须用**窗口模式**（`godot --path . res://xxx.tscn`，不要 `--headless`）。

#### 任务 B：待机微动作（新文件 `scripts/entities/miku_idle_motion.gd`）
- **只在 `MikuModel` 与载入模型之间插一层 `IdleMotion` 节点**，微动作用在该层 →
  和 `player.gd` 写 `MikuModel` 的站/蹲/趴姿态（rot/pos）**物理隔离**，互不打架。
- 三层正弦：① 呼吸（Y 升沉 + 极轻微整体缩放脉动）② 重心微移（X 左右 + Z 前后，小椭圆）③ 上身摆动（Y/Z/X 转动）。
- **无循环接缝的原理**：三频取**互不成整数比**（默认 0.24/0.14/0.18 Hz）→ 合成波长极长；每通道叠二次谐波。全正弦驱动 = C1 连续。
  数值实测：60 fps 相邻帧最大跳变 `0.0007 m` / `0.0011 rad`；扫过 60 s 相位的二阶差分峰值 **3.6e-5**（≈ 无断裂）。
- **趴下自动淡出**：`MikuModel._process` 按**世界「上方向」**判定倾斜（不依赖调用方，player.gd / bot.gd 通用），
  指数平滑把 `intensity` 从 1 拉到 0。实测站立 1.000 / 平躺 0.000。
- **调参位置**（`miku_model.gd` 顶部两张表，键 = 模型目录名）：
  `DEFAULT_IDLE_PROFILE`（默认，轻微，避免盖过自带动画）+ `IDLE_PROFILES`（目前只给 `miku_statue` 调了一组：呼吸更沉、摆动更明显）。
  参数含义（幅度 = 米/弧度/比例，频率 = Hz）在 `miku_idle_motion.gd` 顶部注释。
- 实测幅度与配置吻合：`miku_statue` 位置 `x±0.052 y±0.039 z±0.028 m`、旋转 `y±0.096 rad`；其余约 0.5×。
- 离屏实拍 `miku_statue` 四个相位（0/1.25/2.5/3.75 s）：重心左→右→中→左摆动弧 + 头部偏转 + 双马尾跟随，四点无破面、脚不离地。

#### 关键坑（本轮踩到的）
1. **离屏取景用的包围盒必须排除道具** —— 先用「全部网格」包围盒摆相机，`miku_classic` 的展示台把包围盒撑到跨 10.9 单位、
   中点偏出角色，相机几乎贴地侧看 → 一度**误判「模型躺平了」**。改用**骨骼包围盒**取景后立刻是正常站姿。
   结论：几何异常先怀疑测量，再怀疑模型。
2. **`--check-only` 不解析 `class_name`** —— 单脚本检查会报「找不到 MikuIdleMotion」，必须先跑一次全项目 `--import`
   建立全局类缓存，之后的检查才可信。
3. **`queue_free()` 帧末才释放** —— 展示台要在量包围盒前真正消失 → 用 `remove_child()` + `free()`（先 detach 再 free）。
4. **探针别复用同一个 `MikuModel` 节点多轮测试** —— `_ready()` 会用默认路径自动 `load_model()` 一次，
   再手动调一次 = 加载两遍，打印混进上一轮残留、读数全错。改成每轮新建节点 + `model_path` 指向不存在的路径。
5. `global_transform.basis.orthonormalized().y.y` 是判断「立/躺」的干净量（1 = 直立，0 = 平躺）。

### 🟥 关键发现：`friendly` 组是双重语义（主理人逐行核验，**永久性工程事实**）

`friendly` 组**同时是「伤害路由键」和「阵营显示键」**，两者语义不同：

| 位置 | 用途 |
| --- | --- |
| `player.gd:138` | `_setup_remote_player()` → `add_to_group("friendly")`（注释写「当作队友显示」） |
| `weapon.gd:353` | `if collider.is_in_group("friendly")` → `apply_network_damage.rpc_id(authority)`；**否则**走 `apply_damage_to_target.rpc()` **广播** |
| `knife.gd:100` | 同样的分支 |
| `minimap.gd:20` | `ally_group := "friendly"` + `ally_color` 绿 → 画绿点 |
| `teammate_icons.gd:48` | 遍历 `friendly` 画队友图标 |

**语义真相**：`friendly` 实际含义是「**这是个远端玩家**」（所以要路由到他的 authority 而非广播），
UI 层却读成「**这是个盟友**」。团队模式下两者恰好重合；**MVP = FFA 个人死斗下彻底背离** —— 会显示成「绿点友军 + 可击杀」。

⚠ **陷阱**：只把远端玩家移出 `friendly` 修显示 → `weapon.gd:353` / `knife.gd:100` 掉进 `else` 分支 →
伤害从「只发被击中者 authority」变成**广播到所有端** → **联机伤害直接坏掉**。
**结论：显示改动必须与伤害路由解耦一起做。**

**正解**：解耦「身份」与「阵营」——路由改用中性判据（`collider.has_method("apply_network_damage")` 或新增 `remote_player` 组），
显示层另设阵营组。验收条款 **AC-A3b**：联机下 A 击中 B → 伤害只发 B 的 authority、未落广播分支。
已派 engineering-lead 写进「组契约表」+ 新增一条 ADR（「组作为隐式接口」反模式）+ 加「改动前置检查：改组归属必须 grep 全部 `is_in_group` 消费点」。
