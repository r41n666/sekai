# ADR-006 · 无服务器权威的取舍：手雷伤害只本地结算

> **状态（Status）**：Accepted（已采纳 · 回溯记录，含明确升级路径）

## Context（背景与问题）

本项目是「房主即服务器」的 P2P（ENet 直连）架构，**没有权威服务器**。这带来一组「谁说了算」的问题：

1. **玩家伤害**：`weapon.gd::_deal_damage()` 对玩家走 `apply_network_damage.rpc_id(对方 authority, ...)`
   —— **让被打的那端自己扣血**（`weapon.gd:353-357`）。即「受害者权威」（victim authority）。
2. **手雷伤害**：`grenade_projectile.gd::_damage_nearby()` **只结算爆点附近的本地玩家**
   （`grenade_projectile.gd:67-75`），**不广播、不汇总** → 会产生「**我端扣血、他端没扣**」的穿帮。
   各端通过 `NetworkManager.net_grenade.rpc(origin, velocity)` 各自模拟一个投掷物（`network_manager.gd:224`），
   视觉一致但伤害不一致。
3. **人机（C-7）**：`bot_manager.gd` 仅本端生成、无 RPC；`weapon._deal_damage` 对 `bot` 组**跳过 RPC**（`weapon.gd:351`）。
4. **皮肤 / 外观 / 角色（C-6）**：`WeaponSkin.selected` / `WeaponVariant.selected` 是本端静态字典，不同步。

设计侧明确：P2 支柱**有意放弃**「匹配 / 排位 / 观战 / 服务器权威」（`pillars.md §2`），
把这些列为「有意的简单化，不是缺陷」。

## Decision（决定）

**接受「无服务器权威」的现状，并显式记录每类伤害的结算归属与已知不一致**，作为 MVP 的有意取舍：

| 对象 | 结算归属 | 一致性 |
| --- | --- | --- |
| 玩家受击 | **受害者端权威**（`apply_network_damage.rpc_id` 只发被击中者） | ✅ 一致（只有被打的端扣血，HUD/震动由他响应） |
| 场景物件（训练靶） | **全端一起结算**（`apply_damage_to_target` `call_local`） | ✅ 一致 |
| 手雷爆炸 | **各端只结算本地玩家**（不汇总） | ❌ **不一致（已知穿帮）** |
| 人机 | **纯本地**（不走 RPC，各端各刷各的） | ❌ 不一致（联机时互相看不见，C-7） |
| 皮肤 / 外观 / 角色 | **纯本端**（静态字典，不同步） | ❌ 不一致（别人看到默认外观，C-6） |

**MVP 保持现状**（不引入服务器权威、不做回滚），对应 `pillars.md` P2 的「放弃服务器权威」；
把手雷权威（C-3）作为**边界情形**记录，并给出**升级路径**（见下）。

## Consequences（后果）

**正面**：
- **零权威基础设施**：无回滚、无延迟补偿、无「服务器 tick」—— 实现与调试成本极低，符合小游戏定位。
- **玩家受击体验最自然**：受害端权威让「掉血 + 相机震动 + HUD」在同一端即时发生，无延迟。
- **基线一致的部分已经一致**：位置（ADR-002）、玩家伤害、场景物件伤害三类是**确定一致**的；不一致的集中在
  手雷 / 人机 / 皮肤三类，且都是**有意简化**。

**负面 / 已知穿帮**（必须在联机验收时重点测，`99_review §8.5`）：
- **手雷**：A 端扔雷炸 B 端 → 只有 A 端（若 B 在 A 端本地，即如果 B 是 A 的远端玩家……实际只结算「本地玩家」）
  会扣血，导致两端生命值不一致。**这是死斗模式的体验穿帮**。
- **人机**：联机时每端各有自己的人机，互相看不见、不计入对方击杀 —— 若人机进入正式对局（⚑L-5 推荐「否」）会造成混乱。
- **皮肤 / 外观**：无社交炫耀价值（别人看不到），这也是设计侧「皮肤纯装饰、不做付费」的经济结论的前提
  （`02_combat_economy.md §5.2`）。

## Alternatives considered（备选方案）

| 方案 | 为何未选（M(方案) 仅作升级路径储备） |
| --- | --- |
| **房主权威结算手雷**（推荐升级路径） | 让房主收到 `net_grenade` 后，**由房主**统一算范围伤害，
  `rpc_id` 把每人该扣的血发给对应端。改动小（`grenade_projectile` + `network_manager`），一致性收益大。**列为 C-3 的候选修复**，但属 Phase 4 范围 |
| **完整服务器权威 + 回滚** | 复杂度爆炸，与 P2 直接冲突；仅当未来做匹配 / 排位时再评估 |
| **让手雷伤害广播到所有端、各端算所有人** | 会引入重复结算与竞态；需一个「唯一结算者」（回到房主权威） |
| **干脆去掉手雷 / 只保留单人** | 不可接受（手雷是 `02_combat` 的既定武器，且联机是核心定位） |

## 影响 / 后续（升级路径）

1. **C-3（手雷权威）**：建议**房主权威结算** —— `net_grenade` 到达房主后，房主遍历玩家算范围伤害并
   `apply_network_damage.rpc_id` 分发。工作量 M。
2. **C-6（皮肤同步）**：把「外观 id / 皮肤 id / 角色模型路径」纳入玩家状态广播（低频 / 变更时可靠 RPC），
   远端节点收到后重套外观（复用 ADR-003 的装配管线）。
3. **C-7（人机同步）**：若人机进正式对局 → 需从「本端生成」改为「房主生成 + 广播」，仿照玩家节点的
   「名单本地重建」（ADR-002）。对齐 ⚑L-5（推荐否）。
4. **C-10（人机刷新边界）**：`bot_manager._random_spawn_position()` 应加「在 80×80 内 + 不在掩体内」校验
   （独立于权威问题，纯本地健壮性）。

> **原则**：在 MVP 明确「无服务器权威」。任何把三类不一致「修成一致」的改动，都必须先确认**不违反 P2 的复杂度护栏**，
> 并优先选择「房主权威」这类**低复杂度**方案，而非完整回滚。
