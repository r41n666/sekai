# ADR-004 · 程序化姿态 / 待机微动作：无动画剪辑模型的降级策略

> **状态（Status）**：Accepted（已采纳 · 回溯记录）
> **日期**：2026-10-06 ｜ **作者**：程基岩（engineering-lead，E3-01）
> **关联**：`entities/miku_procedural_pose.gd`、`entities/miku_idle_motion.gd`、`entities/miku_model.gd`、
> `README §7`（第四点 / 第 5 点 / 5.1）、`design/pillars.md` P3

## Context（背景与问题）

项目接入的 9 个初音模型里，**大多数没有可用的动画剪辑**：
- `miku_statue`：无骨骼、无动画（雕塑型）；
- `miku_classic`：有 `AnimationPlayer` 但只有一条叫 `Take 01` 的动画（名字对不上任何状态）；
- 3 个 PMX 转换模型：无动画剪辑；
- `miku.glb`：即使有动画，骨骼名是损坏编码。

若**只播动画**，这些模型会僵在 T-pose；若**只看 `AnimationPlayer != null`**，`miku_classic` 会「既不播动画、又不启用降级」
（`README §7` 明确记录了这个坑）。同时 `player.gd` 每帧写 `MikuModel` 的站/蹲/趴旋转与高度，**降级动画不能与之打架**。

## Decision（决定）

**采用「两层程序化降级」策略，判定条件落到「有没有匹配到状态剪辑」而非「有没有 AnimationPlayer」**：

1. **程序化步态**（`miku_procedural_pose.gd`，RefCounted）：
   模型**没有匹配到 idle/walk/run 剪辑**时启用；直接摆骨骼 —— 放下 T-pose 手臂、
   行走/跑步循环（大腿摆 + 摆动期屈膝抬脚 + 脚掌补偿 + 身体起伏前倾 + 手臂反相），
   **步频按实际速度自适应**（减少滑步）。骨骼识别是启发式的（MMD 标准名优先，乱码名回退几何法）。
2. **程序化待机微动作**（`miku_idle_motion.gd`，Node3D）：对所有模型生效，插在 `MikuModel` 与「载入模型」之间
   一层 `IdleMotion` 节点；三组正弦（呼吸 / 重心微移 / 上身摆动），频率互不成整数比 → 无循环接缝；
   叠加在自带动画之上（幅度轻微）。
3. **职责隔离（关键）**：`player.gd` 的站/蹲/趴旋转与高度作用在 **`MikuModel` 节点**；
   待机微动作用在 **`IdleMotion` 子层**（`miku_idle_motion.gd:5-7`）。两层各写各的变换，**互不干扰**。
4. **趴下淡出**：`MikuModel::_update_idle_intensity()` 按世界「上方向」判定倾斜，趴下时把微动强度
   指数淡出到 0（`miku_model.gd:158-166`），避免呼吸起伏把趴姿顶起来 / 与贴地互掐。

## Consequences（后果）

**正面**：
- **任何模型都能「动起来」**，不会出现 T-pose 雕像 —— 直接服务 P3「明亮舞台上的可辨识角色」。
- **与动画剪辑正交**：有剪辑的模型播剪辑（微动只是轻微叠加），没剪辑的模型走程序化姿态。
- **与姿态系统正交**：站/蹲/趴、待机微动、程序化步态三层各写各的节点/骨骼，可独立开关与调参。
- **纯程序化、零素材依赖**：不需要给模型补关键帧即可上线（`README §12` 明确「不需要给模型加骨骼或关键帧」）。

**负面 / 已接受的取舍**：
- **观感不如真实动画**：`README §12` 承认「观感自然但没有转身 / 急停过渡动作」。
- **程序化姿态是启发式的**：骨骼识别失败时 `valid=false` 保持原姿态（`miku_procedural_pose.gd:18`）——
  对全新骨骼命名约定的模型可能识别不到。
- **待机微动是「整体位移 / 旋转」不是骨骼级**：对无骨骼模型最明显，对有动画模型只是轻微叠加。
- **趴下是「整个模型绕 X 压平 + 每帧闭环贴地」**，不是趴卧动画（`player.gd:247-259`）。

## Alternatives considered（备选方案）

| 方案 | 为何未选 |
| --- | --- |
| **只用自带动画，没动画就保持 T-pose** | `miku_classic` / PMX 模型会僵住，破坏 P3 可辨识度；美术上不可接受 |
| **给每个模型补关键帧动画** | 素材成本高、且模型骨骼名损坏（`miku.glb`）难以做标准动画；程序化是「零素材」的兜底 |
| **用 IK / 物理骨骼驱动** | 复杂度高、且会与 `player.gd` 的姿态系统抢骨骼；本方案刻意避免骨骼级冲突 |
| **把待机微动也做在 `MikuModel` 层** | 会与 `player.gd` 的站/蹲/趴旋转互写同一节点，产生冲突 —— 因此专门插一层 `IdleMotion` |

## 影响 / 后续

- `判定条件 = 有没有匹配到 idle/walk/run 剪辑` 这条**必须保留**，否则 `miku_classic` 类型会退回 T-pose（`README §12` 踩坑记录）。
- 若未来给模型补真实动画：程序化姿态会自动让位（只保留待机微动的轻微叠加），无需改代码。
- 幅度 / 频率调参入口：`miku_model.gd` 顶部 `DEFAULT_IDLE_PROFILE` / `IDLE_PROFILES`（按模型目录名，见 ADR-005）。
