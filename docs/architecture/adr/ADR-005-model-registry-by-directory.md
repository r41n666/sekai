# ADR-005 · 模型按目录名注册：配置表驱动

> **状态（Status）**：Accepted（已采纳 · 回溯记录）
> **日期**：2026-10-06 ｜ **作者**：程基岩（engineering-lead，E3-01）
> **关联**：`entities/miku_model.gd:19-46/183-198`、`shooting/weapon_variant.gd:26-122`、
> `README §7`（接入新模型的 3 步）、`README §12`

---

## Context（背景与问题）

项目要支持**动态接入新角色模型**（放目录即出现），但每个模型的**朝向 / 展示台道具 / 待机微动幅度**各不相同：

- 朝向：部分 Sketchfab 导出正面朝 **-Z**（与项目约定 +Z 相反），需要额外转 180°，而别的模型不需要；
- 展示台道具：部分导出把「舞台 / 灯光 / 地面 / 投影片」打包进 glb，需要清理（否则污染包围盒测量、渲染成白板）；
- 待机微动：无骨骼的「雕像型」需要更强的摆动，有动画的模型只能轻微叠加。

这些**不能靠统一规则推断**（盲目给所有模型补 180° 会把正常的模型转反），必须**逐模型人工登记**。
同时角色列表要能**自动扫描**（Esc 菜单 / 人机随机外观都用）。

## Decision（决定）

**采用「目录名作为注册键」的配置表驱动**，共三张表 + 一张保留表，全部在 `miku_model.gd` 顶部：

| 表 | 常量 | 键 | 值 | 作用 |
| --- | --- | --- | --- | --- |
| 朝向补正 | `MODEL_YAW_CORRECTION`（`miku_model.gd:19`） | 模型目录名 | 额外偏航（度） | 在 `yaw_offset_deg` 之外**再叠一次**，只影响该模型 |
| 展示台道具 | `MODEL_STRIP_PROPS`（`README §7` 第 4.1 点） | 模型目录名 | 关键字列表 | 按关键字删节点（连同子树），**在量包围盒之前**清理 |
| 待机微动 | `IDLE_PROFILES`（`miku_model.gd:37`） | 模型目录名 | 参数覆盖字典 | 覆盖 `DEFAULT_IDLE_PROFILE` 的幅度 / 频率 |
| 缩放微调 | `MODEL_FIT_SCALE`（`README §7`） | 模型目录名 | 缩放倍率 | 目前为空 = 完全信任自动缩放 |

配套机制：
1. **自动扫描**：`MikuModel.list_available_models()`（`miku_model.gd:183`）遍历 `res://assets/models/<子目录>/*.glb`，
   跳过 `MODEL_DIR_IGNORE = ["weapons"]`（避免人机随机变成一把枪）。角色选择菜单（`game_menu.gd:104`）
   与人机外观（`bot_manager.gd:22`）共用它。
2. **键的语义 = 目录名**，不是文件名（`README §7` 明确：必须带一层子目录，散在根下的 `.glb` 不被识别）。
3. **白名单式清理**：`MODEL_STRIP_PROPS` 只对点名的模型生效 —— `miku.glb` 自带的 `Light`/`Camera` 不能误删
   （`README §12`）。

## Consequences（后果）

**正面**：
- **接入新模型 = 放目录 + 导入 +（可选）登记**（`README §7` 的三步），零代码改动。
- **逐模型特例被隔离**：补正 / 清理 / 微动只影响点名的模型，不动其它模型 —— 避免「修 A 坏 B」。
- **自动发现**：角色列表来自文件系统扫描，不需维护硬编码清单。

**负面 / 需注意**：
- ⚠ **盲目补 180° 是反模式**：`README §12` 明确要求「新模型先做一次朝向实拍（相机放在模型自己的 +Z，看到脸才对）再决定」。
- ⚠ **展示台清单也是逐模型手登记的**：判据 = 「渲染出来不是角色的一部分」才加进表；表是白名单，不是全局黑名单。
- ⚠ **发布版风险**：角色列表靠扫描 `res://assets/models/*/*.glb`，若导出时 `.glb` 不随包导出会失效 ——
  目前只在源码运行下验证（`README §12`）。**发布前需改成固定列表或确保资源随包。**
- **目录名是隐式主键**：重命名模型目录会让三张表全部失配（静默退回默认）。改名时须同步改表。

## Alternatives considered（备选方案）

| 方案 | 为何未选 |
| --- | --- |
| **在模型 glb 里内嵌元数据（朝向 / 缩放 / 清理）** | 需要改模型文件或写导入插件；现有素材已就位，改动面大 |
| **统一规则推断（如「所有 Sketchfab 都补 180°」）** | 会误伤正常模型；朝向必须逐个实测（README 明确反例：`miku` / `miku_ps` 不需要补正） |
| **硬编码角色清单** | 每加一个模型要改代码；扫描更符合「放目录即出现」的目标 |
| **按文件名（而非目录名）注册** | 目录名更稳定（文件名可能变体多样），且与「一个目录一个角色」的物理结构对齐 |

## 影响 / 后续

- 新增模型 SOP（与 `README §7` 一致）：
  1. 放入 `assets/models/<目录名>/<文件>.glb`；
  2. 让 Godot 导入（生成 `.import` 并抽贴图）。
     ⚠️ 命令行 `--import` 会走编辑器代码路径、**可能删掉 `project.godot` 的 Vulkan 锁**（已复发 6 次，
     见 `control_checklist.md` §4-17）⇒ 优先「重新打开项目」让编辑器导入；非要用 `--import`，用后必须 grep 复核该锁。
  3. 做一次朝向实拍 → 决定是否登记 `MODEL_YAW_CORRECTION`；
  4. 若渲染出舞台 / 白板 → 登记 `MODEL_STRIP_PROPS`；
  5. 若需要更强的待机微动 → 登记 `IDLE_PROFILES`。
- 发布（release-ops）前必须评估资源打包与扫描列表的兼容性。
