## 1. 分级判定：**Standard（标准档）**

### 1.1 三档定义（本项目口径）

| 档位 | 含义 | 典型内容 |
| --- | --- | --- |
| **Basic（基础）** | 只保证"看得见、看得清"的底线 | 文字可读（字号/对比度）、无频闪、基本颜色区分、可关闭的震动 |
| **Standard（标准）** | Basic + **不依赖单一感官/单一颜色**的冗余编码 | 色盲友好的敌我编码、关键反馈不单靠颜色、信息多渠道冗余、常用操作可重映射 |
| **Comprehensive（全面）** | Standard + 完整重映射 UI / 屏幕阅读 / 运动削减 / 辅助瞄准等 | 面向广泛障碍类型的完整支持 |

### 1.2 判定结论：**Standard**

**选它的理由（4 条）**：

1. **现有资产已稳超 Basic**：项目已经实装了**动态准星、小地图、指南针、队友图标、击杀日志、死亡界面、血条、弹药**共 8 类 HUD 元件，其中**小地图 + 指南针 + 队友图标构成 3 重方向信息冗余**（就算不看其中一个仍能定向）——这已经超过 Basic 的底线。
2. **够到 Standard 的边际成本很小**：从现状到 Standard，唯一**必须新做**的是「敌我编码不能只靠红绿」（§3）。其余 Standard 项（信息冗余、反馈不单靠颜色）**现状已基本具备**。
3. **Comprehensive 明确过度**：本项目是**单人原型 MVP**（无排位、无匹配、无长期投入），没有屏幕阅读、完整键位重映射 UI 的必要性与预算。**不承诺、不列支**。
4. **与 P3 直接协同**：P3 要求"看得清"，本身就要高对比、低噪声、可辨剪影——可访问性与 P3 是**同一条路**，不是额外负担。

> **一句话**：**承诺 Standard，把 Basic 稳稳兜住，Comprehensive 明确不做。**

## 3. 色盲友好方案（重点）

### 3.1 问题：现状靠"红 vs 绿"编码

| 位置 | 现状编码 | 色盲影响 |
| --- | --- | --- |
| `minimap.gd` 敌方 | 红点 `#FF4738`（1.0, 0.28, 0.22） | 红绿色盲（deuteranopia/protanopia，约占男性 8%）下**红绿难以区分** |
| `minimap.gd` 友方 | 绿点 `#59F28C`（0.35, 0.95, 0.55） | 同上 |
| `crosshair.gd` 击杀标记 | 红 `#FF594D` vs 命中白 | 影响较小（有明度差），但 0.18 s 闪现 + 同为暖色，弱视/色盲下可能漏读 |
| `hud.gd` 低血 / 空弹 | 变红 | 红绿色盲下"变红"可能读不出 |

### 3.2 方案：**形状优先 + 明度次之**（✅ 已决 ⚑AC-1 = A：不做色盲调色板）

> **原则：任何"敌我/危险"信息，都必须有**至少一条不依赖色相的线索（形状或明度）**。

| 措施 | 具体做法 | 落地难度 |
| --- | --- | --- |
| **M1 · 形状差异（首选）** | 小地图上：**敌方 = 实心方点 `□`，友方 = 实心圆点 `○`**（现状两者都是圆）。形状差异对**所有**色盲类型有效 | 低（改 `_draw_group()`：敌方 `draw_rect()`，友方 `draw_circle()`） |
| **M2 · 明度差异** | 敌方标记用**暗底 + 亮描边**（明度对比更强），友方用**中明度实心**；即"高对比 = 敌人" | 低（加一圈描边，已有 `Color(0,0,0,0.55)` 底圈，可强化） |
| **M3 · 队友图标已用形状** | `teammate_icons.gd` 已用**菱形**（`_draw_diamond`），与小地图的圆/方形成区隔 → 保持（⚠ **仅 TDM 生效**；FFA 下无队友、该图标不绘制，见 §3.3） | 已具备 |
| **M4 · 击杀标记加形状** | 命中标记（白 X）与击杀标记（红 X）**已同形**；建议击杀时**加一圈外环**或**放大 X**，用"形状/尺寸"而不仅是颜色区分 | 低 |
| ~~**M5 · 可选色盲调色板**~~ | ➖ **用户已判 ⚑AC-1 = A，不做**（M1+M2 形状/明度编码已覆盖全部色盲类型，换调色板反而更弱） | — |
| **M6 · 低血/空弹不单靠变色** | 低血时**血条加斜纹填充**或**边缘闪烁图标**；空弹时**弹匣数字加下划线/图标** | 中 |

> **✅ 已决执行口径**：**M1 + M2 默认生效**（改 `minimap.gd` 两处 `_draw`），这是**零成本、覆盖全部色盲类型**的最小改动；M4/M6 为次优先（目标层）。**M5 调色板已按 ⚑AC-1=A 排除。**

### 3.3 ⚠ 与 FFA 模式的语义冲突（重要，非色盲问题但同源）

> `99_consistency_review.md` C-2 记载：`player.gd` 把**所有其他玩家**放进 `friendly` 组。但 MVP 是 **FFA 个人死斗（`01_core_loop.md` ⚑L-1）——没有队友**。

| 后果 | 说明 |
| --- | --- |
| 🟥 **小地图会把敌人显示成绿色"友军"** | 每个远程玩家都会是绿点 + 队友图标（菱形 + 名字 + 距离），玩家会误以为"是自己人" |
| 🟥 **同时又是可击杀目标** | 与"绿色=安全"的直觉冲突，属于**严重可访问性/可读性问题**（信息自相矛盾比没有信息更糟） |

**处置建议**（→ handoff 给 design-strategist / engineering-lead）：
1. **FFA 模式**：把其他所有玩家放入 **`enemy` 组**（红/方形标记），**清空 `friendly` 组**；
2. **仅当未来上 TDM（`01_core_loop.md` 方案 B）** 时，才按阵营分组；
3. `teammate_icons.gd` 在 FFA 下**不绘制**（无队友）。

> **⚠ 实现层陷阱（2026-10 · design-strategist 复核补正）**：上面①②③只解决**显示层**，但 `friendly` 组被**复用为伤害路由键** —— `weapon.gd:353` / `knife.gd:100` 用 `is_in_group("friendly")` 判断「这是远程玩家 → 伤害只发给他的 authority」。**若只把远程玩家移出 `friendly`，玩家伤害会走错分支（落到 `apply_damage_to_target` 广播），联机伤害逻辑会坏。**
> **正解：解耦「玩家身份（伤害路由）」与「阵营显示」** —— 路由改用中性判据（如 `has_method("apply_network_damage")` 或独立的中性组），显示层单独分组。**显示改动必须与伤害路由解耦一起做**，否则修可读性会打断联机伤害。已同步 engineering-lead（连带一条伤害路由回归 AC）。

## 4. 视觉噪声预算（Glow + 体积雾 + SSR + 明亮水面）

### 4.1 现状噪声源盘点

| 噪声源 | 现状参数 | 对可读性的风险 |
| --- | --- | --- |
| **Glow** | `bloom 0.2` / `hdr_threshold 0.9` / `intensity 0.8` | 亮面（近白天空、水面高光、白裙）**halation（光晕外溢）** → 边缘变糊，细线 HUD 与远处剪影被"晕开" |
| **体积雾** | `density 0.004` | 远景**减透 + 提亮**，25~35 m 外的敌人可能"融进雾里" |
| **SSR** | `max_steps 96` | 镜面水反射云与角色 → 水面出现**高对比、高空间频率的倒影**，与水面上的实体（出生平台、掩体底座）在视觉上"叠影"，干扰"哪个是真的" |
| **明亮水面** | albedo `#122438` + `metallic 1.0` / `roughness 0.06` | 水面本身**对比度低**（近白天空的倒影铺满），角色与浅色掩体在水面上易"隐形" |
| **近白天空** | `sky_horizon #C2E0FA`，被 ACES/曝光推至近白 | HUD 的**浅色细线**（准星 `#E0F5FF`、指南针刻度 `#D9F2FF`）在近白背景前**对比不足** |

### 4.2 缓解手段（分层）

| 层面 | 措施 | 负责 |
| --- | --- | --- |
| **HUD（最优先）** | 所有 HUD 细线加**暗色描边/底衬**：准星、指南针刻度、队友图标文字 → 保证"任何背景前都读得出" | 美术规格（本文）→ 工程 |
| **角色剪影** | 用描边（H1）+ 假接触阴影（H2）把角色从"亮背景 + 反光水面"里拎出来（详见 `asset_spec_arena.md` §6） | 工程（待评估） |
| **掩体** | 主体避开近白（`#2FB3AE`），配暗色底座压出剪影基线；**限制 emissive ≤ 2 处** | 美术 + 工程 |
| **场景** | 若实测远景发白：微提掩体饱和 `+10%`；**不擅自关**雾/Glow（属用户既有配置） | 待 engineering 实测 |
| **信号色配额** | 品红/灯黄面积 ≤ 画面 5%（`visual_identity.md` §2.3） | 美术 |

### 4.3 关键"亮背景"风险复核

| 风险 | 判定 |
| --- | --- |
| 准星 `#E0F5FF`（0.88,0.96,1.0）在近白天空前 | 🟡 **需描边**。准星是中心视线焦点，一旦看不清 = 直接破坏 P1/P3 |
| 指南针刻度 `#D9F2FF` 在顶部近白天空前 | 🟡 **需暗色底衬**（现状已有 `bar_color #050F1A @ 0.3` 半透底，建议加深到 0.45） |
| 命中标记（白）在近白天空前 | 🟡 白对白 → **建议命中标记加暗描边或改用高饱和青 `#39C5BB`**（击杀仍用品红） |
| 小地图 / 击杀日志（右侧半透明底） | ✅ 已有深色底衬，可读 |
