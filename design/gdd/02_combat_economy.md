## 2. 平衡意图（每把武器的定位）

| 武器 | 定位 | 强项 | 代价 | 制衡设计 |
| --- | --- | --- | --- | --- |
| M4A4 | **全能** | 中距压制、容错高 | 单发伤害低（`25`），需 `4` 发 | 后坐力爬升明显（弹道到第 30 发 `0.5°`），远距离必须点射 |
| USP | **高风险精准副武器** | 单发高（`34`）、`3` 发即杀 | 半自动、需精准；弹匣仅 `12` | 换弹慢（`2.2 s`）、`400 RPM` 上限低 |
| 蝴蝶刀 | **近战高风险高回报** | `2` 刀杀（`130` 伤害）、无需弹药 | 射程仅 `2.2 m`、必须贴脸 | `0.30 s` 挥刀硬直，贴脸时暴露在对方火力下 |
| 手雷 | **区域控制 / 逼位** | 一次逼出掩体、可补残血 | 仅 `3` 颗、`1.6 s` 引信可躲 | 伤害 `70 < 100`，不能满血秒杀 |

**反「主导策略」检查**：
- ❌ 若**步枪伤害高到 34**，手枪会失去存在意义 → 保持 `25`（4 发） vs `34`（3 发）的差异化。
- ❌ 若**手雷伤害 ≥ 100**，会变成「无脑丢雷」→ 保持 `70`，强制「雷 + 补枪」的连招。
- ❌ 若**蝴蝶刀射程 ≥ 3 m**，会盖过手枪的近距职能 → 保持 `2.2 m`。

## 3. 护甲 / 血量 / 伤害衰减规格

### 3.1 现状（真实）
- 玩家生命：`player.gd::max_health = 100.0`（无护甲字段）。
- 人机生命：`bot.gd::max_health = 100.0`。
- 伤害衰减：**无**（hitscan `max_range 200 m` 内全额伤害）。
- 手雷：**有**线性衰减（`blast_damage × (1 - 距离/6)`）。
- 人机对玩家的伤害：`damage_per_shot 11.0`，射击散布 `fire_spread_deg 3.5°`。

### 3.2 设计结论（✅ 已决）

| 层次 | 护甲 | 伤害衰减 | 状态 |
| --- | --- | --- | --- |
| **MVP** | **不引入护甲** | **不引入衰减**（保持 `200 m` 全额） | ✅ **已决（用户判 ⚑E-2）** |
| **目标层** | 可选：`50` 点护甲，吸收 `50%` 伤害，先扣护甲后扣血 | 步枪 `30 m` 后线性衰减至 `70%`；手枪 `20 m` 后衰减至 `60%` | 待议（非承诺） |

> **⚑E-2 状态**：✅ 已决（用户判）——**MVP 不引入护甲与伤害衰减**。现状 TTK（步枪 4 发 / 手枪 3 发 / 刀 2 刀）即 MVP 最终规格。

## 4. 回合经济（✅ MVP 不做，目标层再议）

> ⚠ **状态标注**：**MVP 不引入任何经济系统**（用户已判 ⚑C-3 / ⚑E-3）。本节完整保留作为**目标层设计储备**，MVP 阶段不实现。

### 4.1 现状（真实）
- **无购买系统**：所有武器槽开局即有（`player.gd::_build_weapons()` 收集 `WeaponMount` 下 4 把武器）。
- **补给机制**：**长按 `R` 3 秒补满备弹 / 手雷数量**（`weapon.gd` 与 `grenade.gd` 的 `_reset_hold >= 3.0`）——这是「补给站式重置」，是现状唯一的「经济」，**MVP 保留**（⚑E-4）。
- **无金钱、无购买阶段、无连胜连败补偿**。

### 4.2 经济三方案（目标层储备）

#### 方案 A · 无经济（全解锁）✅ 已采纳（MVP）
| 项 | 规则 |
| --- | --- |
| 获取 | 无金钱；所有武器开局即可用 |
| 消费 | 无 |
| 补给 | 长按 `R` 3 秒补满（现状）——相当于「无限弹药补给站」 |
| 优点 | 零改动、纯技巧对决、与 MVP 范围一致 |
| 缺点 | 缺少「资源取舍」的策略维度 |

#### 方案 B · 回合经济（简化 CS 式）— 目标层待议
| 项 | 规则 |
| --- | --- |
| 获取 | 击杀 `+300`，助攻 `+100`，回合胜利 `+2000`，回合失败 `+1500` |
| 消费 | 回合间购买阶段（`15 s`）：步枪 `2700`、手枪 `500`、手雷 `300/颗`、护甲 `1000` |
| 补偿 | 连败补偿：每连败 1 回合 `+500`（上限 `+2000`）；连胜无加成 |
| 前提 | **需要回合制模式（⚑L-1 选 C）**，当前 FFA 模式无线程承载 |
| 优点 | 强策略深度（Achiever + Challenge） |
| 缺点 | 与「死即重生、5 分钟一局」的 P2 支柱**冲突**；改动大 |

#### 方案 C · 半经济（局内补给）— 目标层待议
| 项 | 规则 |
| --- | --- |
| 获取 | 击杀敌人 `+15 血`（上限 `100`）、`+1 手雷`（上限 `3`） |
| 消费 | 无购买，纯「击杀回报」 |
| 优点 | 奖励进攻（对枪赢的人续航更久），创造「连杀滚雪球」的爽感；改动小 |
| 缺点 | 滚雪球可能破坏竞技公平（需上限约束） |

### 4.3 ✅ 采纳结论（用户已判）

> **MVP = 方案 A**（无经济，与现状一致）✅ → **目标层 = 方案 C**（半经济，改动小、与 FFA 模式兼容，待议）→ **愿景层 = 方案 B**（完整回合经济，仅在采用回合制模式后）。

## 5. 外观与皮肤系统的经济定位

### 5.1 现状（真实）
- **武器外观（模型变体）**：`weapon_variant.gd::VARIANTS`，每槽 2 个模型（如 Rifle 的 AK-47 / M4A4），Esc 菜单切换。
- **武器皮肤**：`weapon_skin.gd`，3 种程序化贴图（`gamma_doppler` 伽玛多普勒 / `fade` 渐变之色 / `blue_steel` 蓝钢）+ 原版，共 4 个选项。
- **角色模型**：`game_menu.gd` 扫描 `assets/models/*/*.glb`（当前 9 个）。
- **关键约束**：**外观与皮肤仅影响本端**（README §12：皮肤「联机不同步」；角色选择「不会同步给其他玩家」）。

### 5.2 经济定位结论（✅ 已决）

| 层次 | 定位 | 状态 |
| --- | --- | --- |
| **MVP** | **纯装饰 + 全解锁**（免费、无门槛、无货币） | ✅ **已决（用户判 ⚑E-5）** |
| **目标层** | 可选**成就解锁**（如「累计 100 杀解锁伽玛多普勒」） | 待议（非承诺） |
| **愿景层** | **可交易皮肤**（仅在解决联机同步 + 有足够玩家基数后） | 远期，非承诺 |

> 决策理由：① 现状就是全解锁；② 皮肤**不同步**意味着它没有社交炫耀价值，做付费/解锁门槛没有意义；③ 符合 P2「不做重度成长」。
> **⚠ 前置工程依赖**：若要让皮肤/外观有社交价值，**必须先解决「皮肤联机同步」**——当前 `WeaponSkin.apply_to()` 只写 `material_override` 于本端，远端玩家看到的是默认外观。此点标注**待 engineering-lead 评估**（见 `99_consistency_review.md` C-6）。
