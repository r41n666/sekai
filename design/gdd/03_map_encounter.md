## 1. 地图规模与尺寸（✅ 80×80 已决）

| 项 | 现状 | MVP 结论 | 理由 |
| --- | --- | --- | --- |
| 场景地面 | `main.tscn` 的 `Ground`：`PlaneMesh` **400×400 m** | **保留 400×400 水面**（不改场景底座） | 大水面提供视觉远景与反射，不增加渲染成本 |
| 竞技场边界 | 无 | **80×80 m**（限缩到水面中央，`|x|>40 或 |z|>40` 为出界水面）✅ | 4 人对枪需要「走得到、看得见」的合理空间（见 §1.1 推导） |
| 出生点 | `SpawnPoints` 4 个 `Marker3D`——**已移至四角 `(±32, ±32)`** ✅（原 `(0,8)`/`(8,6)`/`(-8,6)`/`(0,-8)`，间距仅 14~16 m） | **按对局人数分配**（✅ 本轮裁定，见下）：**4 人 = 四角**；**2~3 人 = 相邻/紧凑簇**（间距降到 `≤35 m`，避免「开局找不到人」） | 死斗需「开局有接敌预期」；四角分散对 4 人正确，但对 2~3 人会让对局空转（G4 实测 64 m 相互不可见）——**按 n 自适应** |
| 掩体 | 无 | **12 处**（采纳 `asset_spec_arena.md` §3 清单）✅ | 落在 8~12 区间上限，四向对称 |
| 垂直空间 | 无（全平面 `y=0`） | **0~4 m**：三级叠箱 `1.0→2.0→3.0 m`（**最高可站面 3.0 m**）+ `4.0 m` 立柱地标（不可站）✅ | 真正做出「高低差博弈」（见 §3） |

### 1.1 尺寸推导（为什么是 80×80）
- **步枪有效交火距**：扩散 `0.12`（静止）时精度良好，玩家习惯中距交火 `25~35 m`（对齐 `01_core_loop.md` 视线长度）。
- **从出生点到中心**：`80×80` 对角约 `113.1 m`，四角到中心约 `45~56 m`——**约 8~12 秒**跑动（`sprint 6.5 m/s`），符合 P2「5 分钟一局」。
- **4 人密度**：`6400 m² / 4 ≈ 1600 m²/人`——足够「不会刚出生就撞脸」，又足够「20 秒内必然接敌」。

### 1.2 出生点分配策略（✅ 本轮裁定 · 按对局人数自适应）

> **裁定（设计侧 · 2026-10-06）**：**出生点分布按对局人数自适应**——这是对「四角分散 vs 就近集中」二选一的取代方案。

| 对局人数 | 分配的出生点 | 出生点间距 | 理由 |
| --- | --- | --- | --- |
| **4 人** | **四角** `(±32,±32)` 各 1 | 最近 `64 m`、对角 `90.5 m` | 4 人必须分散，否则开局即三方撞脸；`world_radius=60` 下四角恰好**互不可见**，4 人各自探索 |
| **3 人** | **三角（4 角取 3；R1 落点 = 去 Spawn4）** | 最近 `64 m`、**对角 `90.5 m`** | ⚠ 三角**必含 1 条对角 `90.5 m`**（正方形去掉 1 个顶点，恒剩 1 条对角线——数学上无法通过「选角」消除，见下「为什么 (乙) 不可行」）。**> `world_radius 60` → 同样依赖 §6 AC-3 定位辅助**，与 4 人一视同仁 |
| **2 人** | **相邻两角**（如 `(-32,-32)` + `(32,-32)`，共用一条边） | `64 m` | ⚠ **仍 > `world_radius 60`** → 依赖 §6 AC-3 的**定位辅助**才能相遇（见下） |
| **1 人 / vs 人机** | 任意 1 点 + 人机刷新 | — | 练习局，无「找人」需求 |

**为什么不是「2 人用相邻两点 = 32 m」**：我最初想用「把 2 人放到中心附近」，但中心是**交战热点 + 掩体区**，会导致「开局 2 秒即撞脸、无准备时间」，违背「出生即有退路 / 出生瞬间不暴露」的既有设计（§2 出生点定义）。**故 2 人仍用相邻角（64 m）**，相遇问题**交给定位辅助（AC-3）**解决——这是更本质的修复：**分散出生是「避免开局即死」，找人是「定位辅助」的职责，两者不该互相将就**。

**裁定补充（2026-10-06 · 3 人「对角 90.5 m」问题）→ 采用 (甲)：3 人一律靠 AC-3，不额外调整。**
> **问题**：3 人落点（R1 的 `idx[0,1,2]`）= `(-32,-32)/(32,-32)/(32,32)`，其中 `(-32,-32)↔(32,32)` 相距 **`90.5 m`**——比 2 人的 64 m **更远**，即「找不到人」在 3 人局**更严重**。（感谢 team-lead 实测指出，本表格原只写了最小值 `64 m`，属口径缺陷，已修正。）
>
> **为什么 (乙)「跳过对角」不可行（数学证明）**：从正方形的 4 个角中任取 3 个，**必然剩余恰好 1 条对角线**（正方形去 1 个顶点 = 两条边的第 3 点，与对角顶点仍成对角）。枚举 4 种选角组合，**全部**恰含 1 对 `90.5 m`：
> - `(0,1,2)` → 对角 `(0,2)`；`(0,1,3)` → 对角 `(1,3)`；`(0,2,3)` → 对角 `(0,2)`；`(1,2,3)` → 对角 `(1,3)`。
>
> 即 **`idx` 顺序改成 `0,1,3` 也照样有 `90.51 m` 对角**——(乙) 无法通过「改分配顺序」实现，**除非把某个出生点移出角点**（如放在某条边中点），但那是**新几何**，违背 §2「出生即有退路、背墙朝外」的既有设计。
>
> **结论（甲）**：**3 人接受这条 `90.5 m` 对角，与 4 人交角一视同仁——都靠 §6 AC-3 的小地图边缘三角箭头解决**。理由：① AC-3 本就是「给所有雷达外敌人方向指示」，覆盖 `64 m` 与 `90.5 m` 无差别；② 3 人局非 G4 关键路径（G4 = 2 人 FFA）；③ 改造角点几何的代价远高于收益，且会引入新的「出生点安全性」问题。**不新增任何按人数的分支逻辑**——`idx % 4` 对 2/3/4 人已给出正确分布。
>
> **⚠ 口径统一**：**「雷达外敌人一律靠 AC-3 定位」——适用于 2/3/4 人全部情况，不因人数调整出生点。** 今后若有人质疑「3 人对角太远」，答案固定在本文。

> **⚠ 实现注记（稳定性 · 已与工程侧对齐）**：原 `_spawn_point_for = id % count` **不可预测**（ENet peer id 是大随机数，取模每次不同；id 差为 `count` 整数倍时还会撞同一点）。工程侧 R1 已改为**按房间内排序列表的下标稳定分配**（`spawn_index_for(id, ordered_ids, count)`，`count` = 场景 Marker 数 `4`），即 `ordered_ids.sort()` 后的 `idx % 4`。
>
> **本裁定的可满足性验证（设计侧已核）**：`main.tscn` 的 Marker 顺序为 `Spawn1(-32,-32) → Spawn2(32,-32) → Spawn3(32,32) → Spawn4(-32,32)`，故
> - **4 人** → idx `0/1/2/3` → **四角** ✅；
> - **3 人** → idx `0/1/2` → `(-32,-32)/(32,-32)/(32,32)` = **三角（去掉 Spawn4）** ✅（含 1 条 `90.5 m` 对角，靠 AC-3 覆盖，见上「裁定补充 (甲)」）；
> - **2 人** → idx `0/1` → `(-32,-32)/(32,-32)` = **相邻两角（共用 `z=-32` 边）** ✅。
>
> 三者**均满足本 §1.2**，且各端基于同一份排序列表、结果天然一致（无需新增分支逻辑）。**⚠ 但顺序依赖**：`Spawn1~4` 的子节点次序即是「分配优先序」，**今后新增/重排 Marker 会改变 2/3 人落点**——任何对 `SpawnPoints` 子节点的增删/排序，必须回头核对本节。此约束已同步工程侧（见 EP-1 ES-1.1 修订）。

## 3. 遭遇节奏（Encounter Pacing）

| 维度 | 参数 | 说明 |
| --- | --- | --- |
| **视线长度（Sightline）** | 主通道 `25~35 m`；掩体间隙 `8~15 m`；侧路 `≤15 m` | 主通道给中距步枪博弈；间隙给近距手枪/刀；侧路给短兵相接 |
| **掩体密度** | 12 处 / `80×80`（≈ 每 530 m² 一处） | 太密 → 「躲猫猫」；太疏 → 「谁先看见谁赢」 |
| **垂直空间** | `0~4 m`：可站面 `1.0 / 1.1 / 2.0 / 3.0 m`；`4.0 m` 仅作地标（不可站） | 上高台可俯视但暴露（`+3 m` 高度差在 `30 m` 外约 `5.7°` 俯角，属可接受）；唯一制高点避免「高台架枪统治」 |
| **转向频率** | 主通道直通（低转向）；掩体/转角墙区需频繁转向（高转向） | 制造「直道冲刺」与「拐角谨慎」的节奏交替 |
| **遭遇间隔** | 目标 `8~15 s` 一次接敌 | 通过「出生点—中心 8~12 s 跑动 + 掩体拉扯」实现 |

**心流落地**：遭遇节奏与 `01_core_loop.md` 的张力曲线一一对应——**开阔区（高张力交火）↔ 通道/侧路（张力回落、重新定位）**。

### 3.1 与 `bot_manager.gd` 的刷新约束
- 现状：人机在**玩家周围 8~18 m** 随机方向刷新（`spawn_min_distance 8.0` / `spawn_max_distance 18.0`）。
- **冲突风险**：`80×80 m` 地图下，人机有概率刷到水面（出界区）或掩体内部。
- **MVP 处理**：人机刷新点增加「必须落在地图边界内（`|x|,|z| ≤ 40`）且不与掩体碰撞」的校验（属工程改动，见 §4 / §6）。
- **⚠ 已知限制延续**：人机**仅本端生成、不同步**；且 **✅ L-5 = 人机不进正式对局**（只作练习）。

### 5.3 布局设计意图
1. **四向对称**：避免「背图优势」（`asset_spec_arena.md` §3.2 自检：清单 #1↔#2、#3↔#4、#5~#8、#9↔#10 均中心对称）。
2. **中心开阔、外围有掩体**：中心迫使中远距离对枪（步枪），外围掩体给绕后/逃生（手枪/刀）。
3. **两条侧路**：给被压制者逃生与绕后空间。
4. **单个高台组**：有限垂直博弈，唯一制高点避免「架枪统治」。
5. **出生点背靠墙朝外**：重生后不暴露于中心视线。

### AC-1（对应 C-8）· 出生点必须四角分散 —— ✅ 已解决（工程已实现）
- **原现状值**：`main.tscn` 4 个 `Marker3D` = `(0,0.5,8)` / `(8,0.5,6)` / `(-8,0.5,6)` / `(0,0.5,-8)`——**全部落在中心 `16×16 m` 内**，任意两点间距仅 `14~16 m`。
- **✅ 现状值（已修复）**：四角 `Spawn1 (-32,0.5,-32)` / `Spawn2 (32,0.5,-32)` / `Spawn3 (32,0.5,32)` / `Spawn4 (-32,0.5,32)`——各点 `|x|,|z| = 32 ≥ 24`，最近两点距 `64 m ≥ 45 m`，均在边界内（`≤40`）。
- **判定方法**：遍历 `SpawnPoints` 子节点，断言 ① `abs(pos.x) ≥ 24` 且 `abs(pos.z) ≥ 24`；② 任意两点 `distance ≥ 45`；③ 在边界内。**当前代码已全绿 ✅**。

### AC-2（对应 C-5）· 小地图显示半径须覆盖整张地图 —— ✅ 已解决（工程已实现）
- **原现状值**：`scripts/ui/minimap.gd::world_radius = 45.0`（米）。
- **冲突**：`80×80 m` 地图**对角半长 = √(40²+40²) ≈ 56.6 m** > `45 m` → 地图对角处的掩体/敌人不显示。
- **✅ 现状值（已修复）**：`world_radius = 60.0`（工程侧已设置）——完整覆盖 `56.6 m` 并留 `3.4 m` 余量。
- **判定方法**：断言 `minimap.gd` 的 `world_radius ≥ 56.6`（当前 `60` ✅）。

### AC-3（新增 · C-17）· 超出小地图半径的敌人必须给出**方向指示** —— ✅ 已实现（R2 `b370974`）
> **背景（G4 实测缺口）**：`minimap.gd::_draw_group()` 原逻辑是 `if pos.distance_to(center) > radius: continue` → **超出 `60 m`（对角可达 `90.5 m`）的敌人被整个丢弃**，既不在图上、也无任何方向提示。2 人 FFA 出生在相邻角（`64 m`）时，**双方互相不可见、不可定位** → 无法稳定相遇 → 卡死 G4。（**注**：R2 `b370974` 已实现本条修复——超距改为画边缘箭头；此处保留「缺口背景」以记录设计依据。行号易随重构漂移，故引用函数名而非行号。）

- **🚫 不采纳 (a) 扩大 `world_radius` 到 ≥95**：会让**全图敌人始终可见**，摧毁 FFA 的「潜行 / 绕后」张力（与 P2「快节奏但仍有博弈」冲突），且小地图密度骤降、可读性变差。**不改 `world_radius`（保持 60）**。
- **✅ 采纳 (b) 超半径敌人夹到小地图边缘画「方向箭头」**（指示方位，不给精确距离）：
  - **规则**：对每个敌对目标，`if pos.distance_to(center) > radius` → 在**圆周边缘**（半径 `radius - 2px`）沿「中心→敌人」方向画**三角箭头**（敌对色 `#FF4738`），**不画点、不画距离**。
  - **语义**：「那个方向有人，但不在你雷达范围」——只给方位，保留「他要靠近才进雷达」的潜行价值。
  - **适用范围（口径统一）**：**本 AC 覆盖 2/3/4 人全部情况的雷达外敌人，不因人数调整出生点**——2 人（相邻角 `64 m`）、3 人（含 `90.5 m` 对角）、4 人（对角 `90.5 m`）一律靠本箭头定位（见 §1.2「裁定补充 (甲)」）。
  - **多个超距敌人**：箭头按角度分布，同类箭头**重叠时合并**（MVP 简化，不做防重叠布局）。
  - **形状编码（对齐 M1/Standard）**：箭头为**三角形**（区别于范围内的**方形**敌点 □），确保「仅颜色」之外仍有形状区分。
- **判定方法**：① 构造敌人在 `70 m` 处（`60 < 70`）→ 断言小地图上该方向上**出现三角箭头**、且**不出现在半径内**；② 敌人在 `50 m` 处 → 断言为**范围内核敌方点 □**、无箭头。
- **⚠ 归属**：属 **EP-4（HUD/UX）范围**（`minimap.gd` 绘制），**不在 EP-1（几何）**。
