## 1. 地图规模与尺寸（✅ 80×80 已决）

| 项 | 现状 | MVP 结论 | 理由 |
| --- | --- | --- | --- |
| 场景地面 | `main.tscn` 的 `Ground`：`PlaneMesh` **400×400 m** | **保留 400×400 水面**（不改场景底座） | 大水面提供视觉远景与反射，不增加渲染成本 |
| 竞技场边界 | 无 | **80×80 m**（限缩到水面中央，`|x|>40 或 |z|>40` 为出界水面）✅ | 4 人对枪需要「走得到、看得见」的合理空间（见 §1.1 推导） |
| 出生点 | `SpawnPoints` 4 个 `Marker3D`——**已移至四角 `(±32, ±32)`** ✅（原 `(0,8)`/`(8,6)`/`(-8,6)`/`(0,-8)`，间距仅 14~16 m） | **四角分散**：`(±32, ±32)`，间距 ≥45 m ✅ **已实现** | 死斗模式需 4 人分散、避免开局即死（对齐 `01_core_loop.md` §4 方案 A + `asset_spec_arena.md` §3.2） |
| 掩体 | 无 | **12 处**（采纳 `asset_spec_arena.md` §3 清单）✅ | 落在 8~12 区间上限，四向对称 |
| 垂直空间 | 无（全平面 `y=0`） | **0~4 m**：三级叠箱 `1.0→2.0→3.0 m`（**最高可站面 3.0 m**）+ `4.0 m` 立柱地标（不可站）✅ | 真正做出「高低差博弈」（见 §3） |

### 1.1 尺寸推导（为什么是 80×80）
- **步枪有效交火距**：扩散 `0.12`（静止）时精度良好，玩家习惯中距交火 `25~35 m`（对齐 `01_core_loop.md` 视线长度）。
- **从出生点到中心**：`80×80` 对角约 `113.1 m`，四角到中心约 `45~56 m`——**约 8~12 秒**跑动（`sprint 6.5 m/s`），符合 P2「5 分钟一局」。
- **4 人密度**：`6400 m² / 4 ≈ 1600 m²/人`——足够「不会刚出生就撞脸」，又足够「20 秒内必然接敌」。

## 3. 遭遇节奏（Encounter Pacing）

| 维度 | 参数 | 说明 |
| --- | --- | --- |
| **视线长度（Sightline）** | 主通道 `25~35 m`；掩体间隙 `8~15 m`；侧路 `≤15 m` | 主通道给中距步枪博弈；间隙给近距手枪/刀；侧路给短兵相接 |
| **掩体密度** | 12 处 / `80×80`（≈ 每 530 m² 一处） | 太密 → 「躲猫猫」；太疏 → 「谁先看见谁赢」 |
| **垂直空间** | `0~4 m`：可站面 `1.0 / 1.1 / 2.0 / 3.0 m`；`4.0 m` 仅作地标（不可站） | 上高台可俯视但暴露（`+3 m` 高度差在 `30 m` 外约 `5.7°` 俯角，属可接受）；唯一制高点避免「高台架枪统治」 |
| **转向频率** | 主通道直通（低转向）；掩体/转角墙区需频繁转向（高转向） | 制造「直道冲刺」与「拐角谨慎」的节奏交替 |
| **遭遇间隔** | 目标 `8~15 s` 一次接敌 | 通过「出生点—中心 8~12 s 跑动 + 掩体拉扯」实现 |

**心流落地**：遭遇节奏与 `01_core_loop.md` 的张力曲线一一对应——**开阔区（高张力交火）↔ 通道/侧路（张力回落、重新定位）**。

### 3.1 与 `bot_manager.gd` 的刷新约束
- 现状：人机在**玩家周围 8~18 m** 随机方向刷新（`spawn_min_distance 8.0` / `spawn_max_distance 18.0`）。
- **冲突风险**：`80×80 m` 地图下，人机有概率刷到水面（出界区）或掩体内部。
- **MVP 处理**：人机刷新点增加「必须落在地图边界内（`|x|,|z| ≤ 40`）且不与掩体碰撞」的校验（属工程改动，见 §4 / §6）。
- **⚠ 已知限制延续**：人机**仅本端生成、不同步**；且 **✅ L-5 = 人机不进正式对局**（只作练习）。

### 5.3 布局设计意图
1. **四向对称**：避免「背图优势」（`asset_spec_arena.md` §3.2 自检：清单 #1↔#2、#3↔#4、#5~#8、#9↔#10 均中心对称）。
2. **中心开阔、外围有掩体**：中心迫使中远距离对枪（步枪），外围掩体给绕后/逃生（手枪/刀）。
3. **两条侧路**：给被压制者逃生与绕后空间。
4. **单个高台组**：有限垂直博弈，唯一制高点避免「架枪统治」。
5. **出生点背靠墙朝外**：重生后不暴露于中心视线。

## 6. 工程验收条款（可写成测试用例 · 带具体数值）

### AC-1（对应 C-8）· 出生点必须四角分散 —— ✅ 已解决（工程已实现）
- **原现状值**：`main.tscn` 4 个 `Marker3D` = `(0,0.5,8)` / `(8,0.5,6)` / `(-8,0.5,6)` / `(0,0.5,-8)`——**全部落在中心 `16×16 m` 内**，任意两点间距仅 `14~16 m`。
- **✅ 现状值（已修复）**：四角 `Spawn1 (-32,0.5,-32)` / `Spawn2 (32,0.5,-32)` / `Spawn3 (32,0.5,32)` / `Spawn4 (-32,0.5,32)`——各点 `|x|,|z| = 32 ≥ 24`，最近两点距 `64 m ≥ 45 m`，均在边界内（`≤40`）。
- **判定方法**：遍历 `SpawnPoints` 子节点，断言 ① `abs(pos.x) ≥ 24` 且 `abs(pos.z) ≥ 24`；② 任意两点 `distance ≥ 45`；③ 在边界内。**当前代码已全绿 ✅**。

### AC-2（对应 C-5）· 小地图显示半径须覆盖整张地图 —— ✅ 已解决（工程已实现）
- **原现状值**：`scripts/ui/minimap.gd::world_radius = 45.0`（米）。
- **冲突**：`80×80 m` 地图**对角半长 = √(40²+40²) ≈ 56.6 m** > `45 m` → 地图对角处的掩体/敌人不显示。
- **✅ 现状值（已修复）**：`world_radius = 60.0`（工程侧已设置）——完整覆盖 `56.6 m` 并留 `3.4 m` 余量。
- **判定方法**：断言 `minimap.gd` 的 `world_radius ≥ 56.6`（当前 `60` ✅）。
