**互斥规则（现有 `game_ui` 组机制）**：`Esc 菜单` / `死亡界面` / `人机面板` 三者互斥（打开一个自动关掉其它，`game_menu.gd::_close_other_uis()`）。**新增 `结算面板` 加入同一互斥组**——它是终态，打开时其它界面一律关闭。

**⚠ 现状约束（README §12）**：以上任何界面打开时**游戏不暂停**（人机照常行动、对局计时继续）。UX 必须与此一致——**界面是「覆盖层」，不是「暂停态」**。

## 3. 新增 UI 规格

### 3.1 比分板 Scoreboard（LIVE 常驻）

| 项 | 规格 |
| --- | --- |
| 位置 | 屏幕**顶部中央**（指南针下方、HUD 安全区内），半透明深色底衬（沿用 `#050F1A @ 0.45`） |
| 布局 | 横向一行：`[目标] 先到 15 杀　剩余 03:24`，下方一行 4 个玩家条目 `名字  击杀数` |
| 排序 | 按击杀数降序；**领先者加亮**（亮色 + 加粗）；玩家本人条目加 `▶` 前缀 |
| 更新 | 由 `ScoreManager.score_changed` 信号驱动（见 `01_core_loop.md` 附录 A），实时刷新 |
| 临界提示 | ① 某玩家到 **14 杀** → 该条目闪烁 + 播报「还差 1 杀」；② 剩余 **≤30 s** → 计时器变亮 + 「终局冲刺」提示 |
| 可读性 | 数字用**明度对比**而非仅靠颜色（见 §6）；领先高亮同时用**加粗+亮度**，不只换色 |
| 可访问性 | 底衬保证近白天空前可读；数字字号 ≥ 16（对齐 §6 的 Standard） |

> **⚑F-1 ✅ 已决（用户判）**：**常驻紧凑条**（常显比分与计时）+ **按 `Tab` 展开完整榜**（含死亡数/KD）+ **结算面板给完整榜**。理由：FFA 的「抢 15 杀」需要玩家随时看到比分，符合 P2 短局节奏；`Tab` 完整榜承接「想细看」的需求，避免常驻条占屏。

#### 3.1.1 Tab 完整榜（按住 `Tab` 显示）

| 项 | 规格 |
| --- | --- |
| 触发 | **按住 `Tab`** 显示、松开隐藏（新增输入动作 `scoreboard`，默认键 `Tab`） |
| 模态性 | **非模态覆盖层**——**不进** `game_ui` 互斥组、**不屏蔽输入**（可边看边打，对齐主流习惯） |
| 内容 | 全员表：`排名 / 名字 / 击杀 / 死亡 / KD`；玩家本人条目加 `▶` 并加亮，领先者加粗 |
| 呈现 | 屏幕**中央偏上**半透明深色面板（沿用 `#050F1A @ 0.55`）；字号 ≥ 16；数字用**明度对比**而非仅颜色 |
| 数据 | 与常驻紧凑条同源：`ScoreManager.score_changed`（`01_core_loop.md` 附录 A） |
| 互斥 | 死亡界面 / 结算面板打开时，`Tab` 榜**不响应**（避免叠加） |

### 3.2 结算面板 MatchResult（终态）

| 项 | 规格 |
| --- | --- |
| 触发 | `ScoreManager.match_ended(winner_id, final_scores)`（胜利条件达成，见 `01_core_loop.md` §4 / 附录 A） |
| 结构 | 全屏面板：标题「对局结束」→ 胜者行「🏆 {名字} 获胜」→ 完整比分表（排名 / 名字 / 击杀 / 死亡 / KD）→ 本局时长 → 按钮区 |
| 按钮 | **[再来一局]**（仅房主可点；客户端显示「等待房主…」）｜ **[返回大厅]**（`NetworkManager.leave_game()` 或 `change_scene(hub.tscn)`） |
| 互斥 | 加入 `game_ui` 组；打开时关闭 Esc 菜单/死亡界面/人机面板 |
| 暂停 | **不暂停**（对齐现状；但结算态下对局逻辑已停止计分） |
| 复用 | 参照 `death_screen.tscn` 的面板结构；按钮样式沿用 `game_menu.tscn` 的 StyleBox |

### 3.3 死亡界面 + 重生倒计时（改造现有）

| 项 | 规格 |
| --- | --- |
| 现状 | 「你已阵亡」+ [重生] 按钮（点击立即重生） |
| 新增 | 按钮上方加**倒计时**「3 / 2 / 1」；归 0 **自动**调用 `player.respawn()`（⚑L-4 ✅ 已决 = 3 s） |
| 提前重生 | **[立即重生]** 按钮保留（点击即跳过倒计时） |
| 数据 | 复用 `player.died` 信号 + `player.respawn()`；**无需新系统** |
| 竞速公平 | 重生点 = **离最近敌人最远的出生点**（`01_core_loop.md` §6「复活选点」），避免重生即被架枪 |

### 3.4 加载 3-2-1 倒计时（对局开始）

| 项 | 规格 |
| --- | --- |
| 触发 | `match_state → COUNTDOWN`（房主状态机）；跨端传输 = `01_core_loop.md` 附录 A.4 的 `sync_match_state`；**UI 绑本端信号 `countdown_updated(remaining)`（附录 A.5），不直接绑 RPC** |
| 显示 | 屏幕**中央**大号数字「3 / 2 / 1」覆盖层；由信号 `countdown_updated(remaining)` 取值、本地平滑递减，`sync_match_state` 心跳（1 s）校正 |
| 输入 | COUNTDOWN 全程 `set_input_blocked(true)`；进入 `LIVE` 时 `false` + 重新 `capture_mouse()`（见 §4 矩阵） |
| 目的 | 避免「谁先加载完谁先开枪」——本 UI 与 §4 规则 3 是同一要求的「表现 + 逻辑」两面 |
| 模态 | **非模态**覆盖层（不进 `game_ui` 互斥组；无按钮） |
| 离线 | 本端即权威，直接本地倒计时 |
| **依赖** | **`sync_match_state` RPC（`01_core_loop.md` 附录 A.4）—— 与 EP-4 ES-4.4 同批实现** |

## 4. 输入屏蔽矩阵

> 现状由 `PlayerController.set_input_blocked(bool)` + 武器 `set_trigger_enabled(bool)` 实现。✅=可用 / ❌=屏蔽 / ⏳=不可操作但**计时继续** / 🔒=鼠标锁定。

| UI 状态 | 移动 | 跳跃 | 开火 | 开镜 | 换弹 | 切武器 / 姿态 | 摄像机 | 鼠标 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| **LIVE（对局中）** | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | 🔒 |
| **Esc 菜单** | ❌ | ❌ | ❌ | ❌ | ⏳（计时继续，README §8.1） | ❌ | ❌ | 释放 |
| **死亡界面 / 倒计时** | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ | 释放 |
| **人机面板（H）** | ❌ | ❌ | ❌ | ❌ | ⏳ | ❌ | ❌ | 释放 |
| **结算面板** | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ | 释放 |
| **Tab 完整榜（非模态）** | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | 🔒（不夺取） |
| **加载 / 3-2-1 倒计时** | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ | 释放 |

**规则**：
1. 任意**模态**界面打开 → `set_input_blocked(true)`，关闭 → `false` 并重新 `capture_mouse()`。**例外：`Tab` 完整榜为非模态覆盖层，不触发屏蔽**（见 §3.1.1）。
2. **换弹是唯一「跨界面继续」的计时**（现状行为，`weapon.gd::_process()` 在 `_trigger_enabled=false` 时仍 `_update_reload()`）——**保留**。
3. 加载倒计时**冻结输入**（`01_core_loop.md` §5.1 状态机「3-2-1 倒计时」），避免「谁先加载完谁先开枪」。**客户端由此得知 COUNTDOWN 的触发时机，仅来自 `sync_match_state`**（`01_core_loop.md` 附录 A.4，设计裁定已定稿）——**这是规则 3 可实现的前提**。
4. **不暂停游戏**（对齐 README §12）：界面是覆盖层。

## 5. 心流对齐（UI 如何服务 `01_core_loop.md` §3.2 的张力曲线）

| 心流阶段 | UI 表现 |
| --- | --- |
| 出生（低谷） | 比分板中性显示；准星扩散收敛（`get_spread()` 回落） |
| 接敌（爬升） | 动态准星张开（连射/移动）；指南针 + 小地图提供方向冗余 |
| 交火（高） | 命中标记（`0.18 s`）、枪口火光、震屏、击杀日志 |
| 交错击杀（峰谷交替） | 击杀日志滚动；比分板领先者条目加亮 |
| 终局冲刺（峰值） | 剩余 `≤30 s`：计时器亮起 + 「终局冲刺」；有人 `14` 杀：该条目闪烁「还差 1 杀」 |
| 结算（释放） | 结算面板：胜者高亮 + 完整比分 + [再来一局] |

> **设计意图**：UI 不制造额外张力，只**放大已有张力**——比分板是「有共同目标」的载体（SDT 关联需求，见 `00_concept_mda.md` §3.2）。

## 6. 可读性接口（对接 `design/art/accessibility.md` · **Standard 基准线**）

### 6.1 色盲友好编码（对接 §3 的 M1/M2）

| 措施 | UI 规格 | 负责 |

| **M1 · 形状优先** | 小地图：**敌对标记 = 实心方点 □**，我方 = 圆点 ○；**FFA 下无我方，全部方点**（见 §6.2） | 工程（`minimap.gd::_draw_group()`） |

### 6.3 受伤反馈（不单靠血条数字 → 对接 §2.1 / §5）

- 现状：受伤 = 相机震动（`add_trauma`）+ 血条掉血，**无受伤音效**（README §12 缺口）。
- **UX 要求**：受伤必须有**第二条非颜色线索**——首选**受伤音效**（`player.gd::take_damage()` 补 `hit_player`），次选屏幕边缘红色渐晕（vignette）。
- **handoff → audio-director**（受伤音效）/ **engineering-lead**（vignette）。
